# 首页控件的统一外观与独立业务

状态：2026-10-17产品与架构建议，待视觉方案确认；尚未据此重写控件。用户已确认首页自定义布局完成，布局归档提交为`ed30df5`。本阶段关注单控件的共同外观与业务分工，继续遵循[唯一布局交互规范1.5](quickstart-home-layout-interaction-spec.md)及[业务对齐基线](quickstart-home-business-widgets-alignment.md)。

## 目标与当前源码

目标是让用户一眼看出所有控件属于同一套Quickstart产品，同时让磁盘、网络、共享等业务能够独立演进。共同外壳、字体、操作和状态提示统一；磁盘进度、网络图表、服务页签等各自表达业务。控件保持既有稳定ID、展示形态、位置能力和尺寸意图。

当前并非没有公共代码，而是公共规则尚未收敛：

| 当前入口 | 已有能力／差异 | 建议去向 |
|---|---|---|
| `web/src/pages/index/components/Card.vue` | 原磁盘、存储服务、Docker、下载、远程、系统以及原网络两卡已经共用标题／图标／settings槽位。标准圆角10px、内边距20px 14px、标题16px，手机另有规则；菜单存在硬编码白底、固定宽度和本地点击管理 | 从现有Card演进统一外壳，保留迁移兼容入口；共享菜单与主题令牌 |
| `NativeBusinessCard.vue`／`NativeBusinessSurface.vue` | 隔离原型复用原业务组件，处理摘要、详情、快照与投影；仍需适配旧卡片样式 | 作为迁移Adapter，逐步让原业务内容通过明确Interface接入；不在外面再套第二层完整卡片 |
| `NetworkConnectionCard.vue`／`NetworkInterfaceCard.vue` | 自有网络卡外框，圆角15px、内边距18px 20px，标题／操作各自实现 | 保留两份独立业务，消费共同外壳与操作样式 |
| `CanvasModule.vue`／`HomeApplications.vue` | 设备和应用有另一组外框、标题、间距规则 | 独立业务内容，统一外壳；不恢复历史通用卡里已替代的近似业务分支 |
| `homeTypography.css`／`WidgetMenu.vue` | 已有共同字阶和键盘菜单，但仍有多处覆盖及旧菜单适配 | 作为共同字阶与菜单行为的既有基础，逐步替换重复样式与监听 |
| `NetworkFlow.vue` | 原网络曲线有独立标题、图例与绘图区，是首页已认可的特征 | 本阶段先对齐外围令牌；保留图表、图例、采样及已验收的伸展行为 |

依据为当前源码读取及用户磁盘截图；截图仅作为外观参考，不替代当前数据／状态验收。截图展示系统盘及3条非系统盘；当前原型首页投影上限是物理盘与RAID合计3项。统一样式不改变该上限，磁盘信息密度以后单独评审。

## 建议的视觉与交互标准

### VS01 卡片骨架

以磁盘卡的结构为视觉基线：

```text
┌───────────────────────────────────────────┐
│ 图标  标题                 主要入口   ⋮    │
│                                           │
│ 独立业务内容：列表／图表／页签／指标       │
│                                           │
│ 必要说明、局部失败或有界清单提示           │
└───────────────────────────────────────────┘
```

统一外框、圆角、背景、内边距、标题基线及正文起点。普通卡片采用细边框和轻量外观；阴影主要用于浮层。标题和内容自然增高，保持当前行布局的等高与内容最低需求。不要求每张卡信息量、内容结构或高度一致。

### VS02 字阶与主题令牌

沿用已验收的原字体口径：Arial、Microsoft YaHei及现有回退；普通桌面标题16px／600，正文14px，辅助文字12px。紧凑标题14px；窄槽继续采用已验收的标题14px、正文13px口径，辅助文字12px。数字指标可有明确的大字号，不能把正文随意当指标放大或缩小。

原Card的桌面圆角10px、上下20px／左右14px内边距、20px标题图标、8px图标间距及12px标题正文间距，作为首版候选值；手机沿用原Card的10px内边距和6px圆角作对照，实际统一效果须在样张里确认。这些是拟统一的令牌值，不表示所有当前控件已经使用相同数值。

令牌集中管理字体、圆角、间距、边框、背景、文字、辅助色、悬浮色和焦点。品牌／业务图标颜色可保留语义，但尺寸与对齐一致。浅色、深色通过同一组语义令牌映射原Quickstart主题变量；菜单也使用主题色。后续应从消费端去除相应重复声明，而非继续叠加`!important`。

### VS03 标题操作

- 标题右侧最多一个主要入口，如文件管理、设备管理、查看全部、配置存储服务。按钮采用同一套轻描边样式、字号、图标间距和焦点规则。
- 其他卡级业务入口归到右侧更多菜单；没有其他动作时隐藏更多按钮，没有主要入口时无需填充占位按钮。
- 主按钮与更多按钮是两个独立交互目标，键盘可以分别访问。点击更多只打开菜单，不触发主入口；不使用可点击父元素包住另一个可点击元素。
- 桌面操作最小视觉高度候选32px，触屏可点击区域至少44px。名称较长时先让标题／操作区自然换行，仍显示可理解的文字；不靠缩小字体或只留无标签图标挤进去。
- 取消重复的卡片右下角详情入口。正文内的磁盘分区动作、Docker开关、服务Web入口仍按业务保留；“卡级最多一个主要入口”不限制正文必要动作。
- 布局编辑中的替换、隐藏、显示设置及尺寸手柄由布局编辑层管理；业务更多菜单只呈现业务动作，编辑期间业务继续inert。

### VS04 共享菜单行为

沿用现有WidgetMenu已实现的上下键、Home／End、Escape、Tab、点击外部关闭与关闭后焦点恢复。菜单根据可用空间对齐，窄屏不超出可视区域，祖先容器不裁切菜单。业务声明动作名称、可用条件与原处理函数，共享菜单只负责显示和交互。

“完整信息”仅在确有摘要／清单截断等需要时提供，不要求每卡机械增加。旧代码中只有模板、没有可用触发路径的动作须单独列为功能变更，不借统一样式静默开放。例如系统信息原模板中的系统监控／备份菜单，目前不能作为已经验收的可用功能。

### VS05 共同状态语言，独立业务判定

加载、空、失败、局部失败、旧快照、未安装、未配置、无权限分别有共同的视觉呈现；状态文字和是否可操作由业务决定。磁盘一项读取失败时，可用数据仍显示；旧快照不标成当前正常；权限说明不能被通用“网络异常”覆盖。

共享状态样式不推断业务。例如磁盘用量颜色仍采用原DiskItem规则，用量高不等于SMART异常；易有云`enabel`、WebDAV路径、Docker状态和DDNS的Stopped／Disabled继续沿用业务基线。样式工作不顺带修复已记录的指标缺值／零值等业务问题。

### VS06 形态与布局

标准／摘要／网格／启动条是现有模块形态，共享同一套外壳规则。已有`widgetPresentation.ts`负责形态、能力及内容上限，外壳不复制第二套判断。形态可以改变信息密度和正文，不能删除原功能入口或靠字号缩放冒充另一形态。

维持自然高度、用户最小行空间、上下分配、窄屏拆行、一次撤销与恢复自动。尺寸测量不反馈到业务字段、形态推荐或列表容量；外壳本身不设置固定行高，也不增加卡内滚动。网络曲线保留320px／手机300px基线及已验收的可伸展组合。

## 每个控件的首版接入对照

以下保留当前已可用的动作及条件，只有外观／组织方式收敛；不是新增业务入口清单。

| 稳定ID／控件 | 标题主要入口 | 更多／正文业务保留 |
|---|---|---|
| traffic 网络流量 | 测速 | 曲线、上传／下载图例和读数保持；本阶段不增加其他图表指标 |
| connection 网络连接和IP地址 | 设备管理 | 连接详情；IPv4／IPv6独立隐私显示、DNS与软件源修复入口保持 |
| networkInterface 网络接口状态 | 配置 | 原接口详情／完整清单，端口名称、链路状态与已知速率 |
| applications 应用与工具 | 全部 | 原应用浏览、常用项管理、图标行数／网格／启动条规则 |
| devices 局域网设备 | 查看全部 | 家长控制；设备定位、在线／本次发现口径、刷新、地址分配权限和缺流量能力说明 |
| storage 磁盘信息 | 文件管理 | RAID管理、S.M.A.R.T.、磁盘管理、挂载点；完整清单及磁盘／分区原操作 |
| sharing 存储服务 | 配置存储服务 | 统一共享高级配置；易有云／SAMBA／WebDAV分页签及原地址、目录、访问动作 |
| docker Docker | Docker迁移 | 原条件下可用的Docker高级配置；启停、安装检查、目录和错误状态 |
| downloads 下载服务 | 下载管理 | Aria2／qBittorrent／Transmission原高级配置、页签、服务状态及Web入口 |
| remote 远程域名 | 域名配置 | 原DDNSTO／IPv4／IPv6页签、链接、控制台和条件下可用的DDNS入口 |
| system 系统信息 | 信息概览 | 摘要的完整信息入口；完整形态三图与型号、固件、内核、时间、启动时长保持 |

磁盘卡首版样张应优先解决：文件管理与更多对齐、分组标题与磁盘条目的层级、型号长文本可读、进度与用量对齐、动作不挤压内容。系统根目录／非系统磁盘／RAID分组及状态不重新定义。原“已挂载磁盘”标题实际包含全部非系统盘的已知口径继续记录，名称修改另作业务决定。

## 实现建议：小Interface、独立Implementation

采用四个Module，复用现有实现逐步收敛：

1. **主题令牌Module**：唯一视觉取值来源；原Quickstart变量作为主题Adapter。卡片和菜单只消费语义变量。
2. **卡片外壳Module**：由原Card演进出共享`HomeWidgetFrame`，原路径在迁移期间作为兼容Adapter。Interface保持标题、已有展示形态，以及图标／主要操作／更多／正文／必要提示的槽位；不接收磁盘对象、所有业务API或巨大的组件配置表。
3. **共享交互Module**：复用WidgetMenu，抽取共同按钮、状态提示、分区标题、键值行和进度条样式中确有重复的部分。业务状态判断、页签、表单和操作函数仍由各业务Module负责。
4. **独立业务Module**：磁盘、网络连接、接口、共享等分别拥有其字段、状态、权限、动作及测试；从既有读取owner消费快照，不因统一外壳多启动一次读取。布局只认识稳定ID、展示能力及渲染入口。

**Seam**位于布局调用控件的既有入口，以及业务填入共享外壳的位置。共享外壳掌管共同外观和标题交互，业务掌管内容与动作。原Card与当前不同原型外框是两类实际Adapter，不为假想的未来插件创建新的注册框架。现有模块定义及形态解析继续复用。

示意Interface（不代表已经实现或确定了文件名）：

```vue
<HomeWidgetFrame :title="title" :presentation="resolved.id">
  <template #icon><DiskIcon /></template>
  <template #primary>
    <WidgetAction @click="openOriginalFileManager">文件管理</WidgetAction>
  </template>
  <template #more>
    <WidgetMenu :items="availableDiskActions" @select="runOriginalAction" />
  </template>
  <DiskContent :snapshot="snapshot" />
  <template #notice><DiskProjectionNotice /></template>
</HomeWidgetFrame>
```

槽位不必全部填写。标题的可访问名称／实例ID由外壳统一处理，不能只用稳定模块ID生成会在详情中重复的DOM ID；动作的名称、可用性、确认步骤与原处理函数由业务传入。详情可复用业务内容，避免嵌套两层标题／边框或启动两份读取owner。

共享代码建议落在`web/src/components/home-widget/`，先由隔离原型引用；原业务文件在正式接入阶段逐项演进。原有业务文件路径可以保留，不为目录美观进行整批搬迁。样式使用命名明确的本地类和共享变量，业务样式只约束本Module内部；不写全局`header`／`button`／`.item`规则。

当前设计构建通过字符串替换和DOM扫描适配原标题菜单，属于保留原业务源码的过渡方式。正式开发时应改为显式动作清单／槽位接入，避免把这类适配扩展成共享组件的长期Interface。

## 推荐推进与可测试标准

先以磁盘卡制作标准外壳样张，覆盖标准／窄槽及深浅主题，确认后锁定共同视觉参数。随后选网络连接作为第二种实际接入：一张是列表，一张是状态与键值，能够验证外壳足够通用。再迁移接口、设备、应用和其余原Card业务；网络图表保持当前内核与特征，最后核对外围一致性。

视觉与行为应分别验收：

- 同形态标题、图标、操作按钮、圆角、边框、内容起点一致；长标题／长目录／英文和深色菜单可读，320px手机及触屏动作不重叠。
- 文件管理仍执行原安装检查和跳转；四个磁盘高级入口与每盘动作可达，主按钮和更多不会互相触发；菜单支持键盘、触摸和焦点恢复。
- 磁盘正常、空、未挂载、未分区、只读、SMART异常、RAID及局部失败保留；文件管理与格式化等不同作用不混淆。布局编辑不提交业务配置。
- 其他控件以既有字段／状态／动作／权限清单逐项回归；共同状态视觉不替代业务计算。
- 用户已验收的结构、形态、上下空间、整行排序、移动／替换、撤销／取消、窄屏往返仍通过；不新增布局选项或第二套偏好存储。
- 不新增业务轮询或无界历史；反复菜单／形态切换、后台恢复及实际卸载后没有多余监听、定时器或图表实例。

本文件只提出统一规范与迁移路线，当前5180仍保留已验收的布局和控件外观。后续样张、当前候选自动化与用户视觉确认必须另留证据，不能用布局通过结论替代控件样式验收。
